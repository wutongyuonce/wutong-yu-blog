# 页面间距维护指南

本项目的首屏间距分为两层：共享布局决定全站的基线，页面组件再微调自己的首个内容。调整时遵循 **先确认目标间距属于哪一层，再只改对应层**；不要为了首页效果去改标题或副标题的共享样式。

## 1. 间距层级与修改顺序

```text
导航栏
  ↓ BaseLayout：导航栏到页面首个标题
标题 / 副标题 / 文章元信息
  ↓ StandardLayout：标题区到正文容器
页面首个可见元素
  ↓ 首页、博客、项目、友链、文章各自的微调
```

| 想调整的视觉距离 | 优先修改 | 影响范围 |
| :-- | :-- | :-- |
| 导航栏与所有页面首行 | `BaseLayout.astro` 的 `<main>` 顶部 padding | 全站非首页、首页与文章页 |
| 标题区与正文的基础距离 | `StandardLayout.astro` 的 `.page-header` / `.post-header` margin | 使用 `StandardLayout` 的页面 |
| 大标题与小标题 | `StandardLayout.astro` 的 subtitle `mt-*` | 所有带 subtitle 的标准页 |
| 某一页面的正文首行 | 对应页面或视图组件的 `margin-top` / `top` | 仅该页面 |
| 文章标题与日期、标签 | `PostMeta.astro` 的 `mt-*` | 仅文章页 |

推荐顺序：先用共享参数做小幅调整；若只有一个页面还不合适，再改该页面的专属参数。一次只改一个值，并同时检查桌面和窄屏。

## 2. 全站共享间距

### 2.1 导航栏到内容首行

文件：[src/layouts/BaseLayout.astro](../../src/layouts/BaseLayout.astro)

```astro
<main id="main" class="px-7 pt-4 pb-10">
```

- `pt-4`（`1rem`）控制导航栏之后、页面内容之前的顶部留白。
- `pb-10` 只影响页面底部，不用于首屏调节。
- `px-7` 只控制左右内边距。

当首页、Blogs、Projects、Friends 和文章页都离导航栏过远或过近时，调整 `pt-4`。例如 `pt-6` 更松，`pt-2` 更紧。不要使用负外边距把 `<main>` 拉进导航区域，容易导致标题与导航重叠。

### 2.2 标题区到正文的基础距离

文件：[src/layouts/StandardLayout.astro](../../src/layouts/StandardLayout.astro)

```astro
<header
  class:list={[
    'page-header prose mx-auto',
    { 'text-center': isCentered, 'post-header': isArticle },
  ]}
>
```

- `.page-header` 的 `margin-bottom: 3.5rem` 是标题区底部到正文容器的共享基线。
- 调大该值会让所有标准页面更疏松；调小会让它们整体靠近。不要改成负值。
- 文章页使用 `.post-header` 覆盖为 `1.75rem`，使元信息与正文的间距接近文章标题与副标题的间距。
- 这个值会同时影响首页、Blogs、Projects、Friends 和文章页；仅某页需要调整时，不要修改它。

### 2.3 大标题与小标题

同一文件中的当前实现：

```astro
{subtitle && <p class={`${isArticle ? 'mt--2!' : 'mt--8!'} op-50 italic`}>{subtitle}</p>}
```

- 标准页面使用 `mt--8!`；文章页使用较宽松的 `mt--2!`，避免多行标题压住 subtitle。
- 这是共享样式；首页正文离 subtitle 太远时，应先改首页正文容器，而不是改这里。
- 该值过于负时会出现 subtitle 压住标题的情况，因此应每次最多改变一到两个 UnoCSS 间距档位后再检查。

## 3. 各页面的专属首屏间距

### 3.1 首页 `/`

首页通过 `StandardLayout` 的 `head` 插槽挂载独立标题区。文件：[src/components/home/HomeHeader.astro](../../src/components/home/HomeHeader.astro)

```css
.home-title-row {
  gap: clamp(2rem, 7vw, 6rem);
}

.home-title-subtitle {
  margin-top: -2rem !important;
}
```

- `gap` 控制标题文字与复古桌面之间的水平距离。
- 屏幕小于 `720px` 时切换为纵向布局。

首页正文与标题区的距离仍在 [src/pages/index.mdx](../../src/pages/index.mdx) 中调整：

```mdx
<div slot="article" class="home-content" style="margin-top: -1em;">
  <RenderPage collectionType="home" id="index" />
</div>
```

这是首页“副标题到第一段正文”的专属调节器。

- 更靠近：把 `-1em` 调得更负，例如 `-1.25em`。
- 更疏松：把它调回 `-1em` 或 `0`。
- 建议每次以 `0.25em` 为步长；正文段落自身还有 `.prose p` 的默认上下外边距，过大幅度会让首段贴住标题区。

### 3.2 Blogs `/blogs/`

首个可见元素是年份装饰标题，而不是普通正文段落。

文件：[src/components/base/Categorizer.astro](../../src/components/base/Categorizer.astro)

```css
.categorizer__label {
  top: -2rem;
}
```

- `top: -2rem` 决定年份文字相对分类容器的上移量，只影响普通 `Categorizer`（博客列表）。
- 需要移动年份视觉位置时改此值；不要为此修改 `StandardLayout`。

文件：[src/components/views/ListView.astro](../../src/components/views/ListView.astro)

```astro
<section data-year={group.year} class="mb-16">
```

这里的 `mb-16` 控制年份分组之间的距离，不控制标题区到第一组年份的距离。

最后一个年份分组通过以下规则清除自身的底部外边距，避免它与 `cd ..` 的统一 `1.5rem` 间距叠加：

```css
.blog-year-group:last-child {
  margin-bottom: 0;
}
```

### 3.3 Projects `/projects/`

Projects 使用紧凑版 `Categorizer`。文件：[src/components/base/Categorizer.astro](../../src/components/base/Categorizer.astro)

```css
.categorizer--wide .categorizer__label {
  position: static;
  font-size: 0.75rem;
  letter-spacing: 0.12em;
}
```

- 分类标题现在参与正常文档流，不再用超大描边字和绝对定位。
- 调整字号、字距或透明度只会影响 Projects 分类标签。

文件：[src/components/views/GroupView.astro](../../src/components/views/GroupView.astro)

```astro
<section class="project-group">
  <Categorizer text={key} wide={true} />
  <GroupItem items={data[key]} />
</section>
```

- `.project-group` 的 `gap: 0.625rem` 控制分类标签与卡片网格的距离。
- `.project-groups` 的 `gap: 2rem` 控制分类之间的距离，移动端为 `1.5rem`。
- `GroupItem.astro` 使用 `minmax(240px, 1fr)` 自适应网格，窄屏回退为单列。

### 3.4 Friends `/friends/`

文件：[src/components/views/FriendsView.astro](../../src/components/views/FriendsView.astro)

```css
.friends-page {
  margin: -1.6rem auto 0;
}
```

这是 Friends 内容区相对于共享标题区的专属上移量。

- 想让友链卡片区靠近页面 subtitle：把 `-1.6rem` 调得更负。
- 想让卡片区更靠下：把它调向 `0`。
- 此外，`.friends-shell` 的 `gap` 控制卡片区与申请友链区之间的距离，不是首屏距离。

### 3.5 文章页 `/blogs/[slug]/`

文章页也使用 `StandardLayout`，但标题区还有元信息。文件：[src/components/base/PostMeta.astro](../../src/components/base/PostMeta.astro)

```astro
<div class="mt--4! op-50 lt-md:text-sm">
```

- 无副标题文章使用 `mt--4!` 控制标题与日期、阅读时间、标签之间的距离；有副标题文章使用 `mt--2!`，让副标题与元信息也保留可读间隔。
- 不要用它调整文章正文；正文与标题区的基础距离由 `StandardLayout` 的 `.post-header` `margin-bottom` 决定。

若文章有封面，文件：[src/components/base/PostCover.astro](../../src/components/base/PostCover.astro) 中远程封面使用：

```astro
class="mb-0! mt--4!"
```

`mt--4!` 只调整封面相对于前一个文章元素的距离。无封面文章不受此设置影响。

## 4. `cd ..` 返回链接与正文的间距

`cd ..` 本身只负责生成返回目标；它与上方正文的间距、宽度和对齐由 [src/layouts/BaseLayout.astro](../../src/layouts/BaseLayout.astro) 中的 `footerStyle` 按当前路由统一设置。首页不渲染这个返回链接。

```ts
const footerStyle: Record<string, string> = { marginTop: '1.5rem' }
```

所有非首页页面的 `cd ..` 都使用 `1.5rem` 间距；首页不渲染返回链接。Friends 与 Insights 仍在各自的路由分支中设置宽度和对齐，但不再覆盖这个统一间距。

若以后需要统一调节，只改这一个 `marginTop` 值。只有明确要让某类页面例外时，才在相应的 Friends、Insights 或文章详情分支中覆盖它。不要在 `BackLink.astro` 中增加 margin；该组件只决定链接文案和返回路径。

## 5. 快速决策

| 现象 | 应改位置 |
| :-- | :-- |
| 每一页都离导航太远 | `BaseLayout` 的 `pt-*` |
| 每一页标题下方正文都太远 | `StandardLayout` 的 `.page-header` `margin-bottom` |
| 只有首页首段太远 | `index.mdx` 的 `home-content` `margin-top` |
| 只有博客年份位置不对 | `Categorizer.astro` 的普通 `.categorizer__label` `top` |
| 只有项目分类标题或卡片距离不对 | 紧凑版 `Categorizer` 的字号/字距，或 `GroupView.astro` 的 `.project-group` / `.project-groups` gap |
| 只有友链卡片区太远 | `FriendsView.astro` 的 `.friends-page` `margin` |
| 文章标题、日期、标签挤压或疏松 | `PostMeta.astro` 的 `mt--4!` / `mt--2!` |
| `cd ..` 离某类页面正文太远或太近 | `BaseLayout.astro` 对应路由分支的 `footerStyle.marginTop` |

## 6. 验证方式

修改后运行：

```bash
pnpm check
pnpm dev
```

至少检查首页、`/blogs/`、`/projects/`、`/friends/` 和一篇带封面的文章；同时确认每个非首页路由的 `cd ..` 没有贴住正文或错位。特别注意窄屏：首页标题区变为纵向，Projects 变为单列，Friends 卡片网格与申请面板也会收缩。
